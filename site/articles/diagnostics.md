# Diagnostic codes

Broadside reads damaged files by repairing them and recording what it repaired, instead of throwing (strict mode throws instead). Each record is a `Diagnostic` with a severity, a message about that occurrence, and a code: a `DiagnosticCode` with a stable name, the area of the library that reports it, its default severity and the clause of the specification it is about. Match diagnostics on the code (`diagnostic.Kind == FileStructureDiagnostics.StartxrefMissing`, or `diagnostic.Code == "StartxrefMissing"`), never on the message, whose wording may change in any release.

`DiagnosticCatalog.All` lists every code at run time, and `DiagnosticCatalog.TryGet` finds one by name. `DiagnosticCode.Description` holds the text the tables below show.

## Stability policy

From version 1.0, diagnostic codes follow these rules:

- **A code is never renamed or reused.** Its name keeps meaning the same kind of deviation for as long as it exists, so code that matches on it keeps working.
- **New codes may appear in any minor release**, when a new feature or a new repair needs one. Handle codes you do not know, for example by their severity.
- **A change to a code's default severity is a documented behavior change.** It is listed in the release notes of the release that makes it, never made silently in a patch.
- **A code is removed only in a major release.** Until then a code that is no longer reported stays in the catalog.
- **Descriptions and messages may be reworded in any release.** They explain codes; they are not part of the contract.

Codes reported by third-party filters, font program parsers and security handlers are made with `DiagnosticCode.Create`, carry their owner's prefix (`Contoso.LicenseExpired`) and are outside this catalog and this policy. Broadside's own names never contain a dot, so the two never collide.

Every change to the catalog is visible in review: the tables below are generated from the catalog and the documentation build fails when they are stale, and a snapshot test in the test suite fails when a code is added, renamed, removed or re-rated until the change is accepted. Release notes link to this page.
