# Adding a rendering backend

> The contract below is the real one, landed by issue #94 (`src/Broadside/Rendering/`, `src/Broadside/PublicAPI.Unshipped.txt`). Later Phase 3 tickets add members to `IRenderingBackend` as their operations enter the display list (strokes, clips, glyph runs, images, shadings, patterns, groups); update the signature list here in the same PR.

A backend is "a concrete implementation of the rendering surface contract that knows how to draw on one technology" (`CONTEXT.md`). Backends consume display lists; nothing renders from content-stream operators directly (ADR 0006, `CLAUDE.md` "Hard rules"). The software rasterizer is the reference every other backend is measured against.

## Where it lives

- Contract: namespace `Broadside.Rendering` in the core package, `src/Broadside/Rendering/` (`DisplayList`, `IRenderingBackend`, `DisplayColor`; the internal `DisplayListBuilder` split into one file per operation category). Types in `Rendering` carry no `Pdf`/`Cos` prefix (`CLAUDE.md`, "Code conventions").
- Software rasterizer, ICC engine and PNG encoder: `src/Broadside.Rendering/` (no native dependencies; Track 3B, 3C).
- Each other backend is its own package: `src/Broadside.Rendering.Skia/` (references `Broadside.Rendering` and `SkiaSharp`), `src/Broadside.Rendering.CoreGraphics/`, `src/Broadside.Rendering.Direct2D/` (CsWin32), `src/Broadside.Rendering.Android/`. A backend may depend on its platform library and nothing else (ADR 0001). The CoreGraphics and Android projects only build when their workloads exist (`-p:BroadsideBuildPlatformBackends=true|false`).
- Tests: `tests/Broadside.Rendering.Tests/` (rasterizer, snapshots), `tests/Broadside.Rendering.Skia.Tests/`, the CoreGraphics macOS test app `tests/Broadside.Rendering.CoreGraphics.Tests/`, and for Android (#133) the device app `tests/Broadside.Rendering.Android.Device/` with the host project `tests/Broadside.Rendering.Android.Tests/` (see "Backends that only draw on a device" below). Direct2D (#129) is the worked example of a platform-only backend: `tests/Broadside.Rendering.Direct2D.Tests` and `bench/Broadside.Rendering.Direct2D.Benchmarks` target `net10.0-windows10.0.19041.0` with `EnableWindowsTargeting`, so they build on every host and sit in `Broadside.slnx` but not in `Broadside.Core.slnf`; the Windows leg of `ci.yml` runs them (`dotnet test --project ...`, `--job dry`) and `format` checks them. Its bindings come from CsWin32 with `allowMarshaling: false` (`NativeMethods.txt`/`NativeMethods.json`): COM interfaces as unmanaged structs called through function pointers, which is trim- and AOT-safe and allocates nothing per call.

## Contract

Namespace `Broadside.Rendering`, core package (ADR 0006: backends consume display lists, never content-stream operators):

```csharp
// Built once per page; immutable; replayable on any number of threads at once, each with its own backend.
public sealed class DisplayList
{
    public PdfDocument Document { get; }               // whose GetColorConverter a backend converts colours through
    public int OperationCount { get; }
    public void Replay(IRenderingBackend backend);     // reads only the list, allocates nothing
    public void Replay(IRenderingBackend backend, PdfRectangle region); // only paints whose bounds meet the region (#96)
    public void Replay(IRenderingBackend backend, CancellationToken cancellationToken, IProgress<double>? progress);   // #97
    public DisplayListReplay BeginReplay(IRenderingBackend backend, CancellationToken cancellationToken, IProgress<double>? progress);
    public DisplayListReplay BeginReplay(IRenderingBackend backend, PdfRectangle region, CancellationToken cancellationToken, IProgress<double>? progress);
}

// #97: a replay in time slices; Continue(budget) hands over operations until the budget is used (at least one), the next resumes.
public sealed class DisplayListReplay { int Position; bool IsCompleted; double Progress; bool Continue(TimeSpan budget); }

public sealed class PdfPage
{
    public DisplayList CreateDisplayList();
    public DisplayList CreateDisplayList(ContentOptions options);   // limits, optional-content state, cancellation
}

public interface IRenderingBackend
{
    void SaveState();                                   // §8.4.2 q (and the state saved around a form XObject)
    void RestoreState();                                // §8.4.2 Q; saves and restores always balance
    void SetTransform(in Matrix transform);             // replaces (does not concatenate) the user space -> default user space transform
    void FillPath(PathView path, FillRule rule, in DisplayColor color);   // §8.5.3.3
    void StrokePath(PathView path, in StrokeStyle style, in DisplayColor color);   // §8.5.3.2, after the fill of B/b (#99)
    void IntersectClip(PathView path, FillRule rule);   // §8.5.4 W/W* (after the paint of its path), §8.10.1 form BBox; restored by RestoreState
    void DrawImage(DisplayImage image, PdfDefaultColorSpaces defaultColorSpaces, ColorConversion conversion);   // §8.9.4, #102; masks #106
    void FillImageMask(DisplayImageMask mask, in DisplayColor color);   // §8.9.6.2 stencil mask in the fill colour, #106
    void BeginAnnotation(in DisplayAnnotation annotation);             // §12.5.5 an annotation's appearance begins (a save), #98
    void EndAnnotation();                                              // composite it, restore
    void DrawGlyphs(in GlyphRun run);   // §9.4.3, §9.3.6, #100: Program, FontMatrix, RenderingMode, Glyphs (GlyphId, TextMatrix, HorizontalScale), GetOutline(i), GetGlyphTransform(i), Fills/FillColor, Strokes/StrokeStyle/StrokeColor
    void DrawShading(in DisplayShading shading);   // §8.7.4.2 sh: fills the current clip, no Background (#109)
    void FillPathWithShading(PathView path, FillRule rule, in DisplayShading shading);   // §8.7.4.1 shading pattern fill, with Background (#109)
    void StrokePathWithShading(PathView path, in StrokeStyle style, in DisplayShading shading);   // §8.7.4.1 shading pattern stroke (#109)
    void FillPathWithTilingPattern(PathView path, FillRule rule, in DisplayTilingPattern pattern);   // §8.7.3 tiling pattern fill: Pattern, Matrix (pattern space), Cell (a DisplayList in pattern space) (#112)
    void StrokePathWithTilingPattern(PathView path, in StrokeStyle style, in DisplayTilingPattern pattern);   // §8.7.3 tiling pattern stroke (#112)
    void SetCompositing(double strokeAlpha, double fillAlpha, BlendMode blendMode);   // §11.6.4.4 CA (strokes) / ca (all else), §11.6.3 BM, §11.3 formulas; saved/restored with the state, starts 1/1/Normal (#113)
    void SetDeviceParameters(in DisplayDeviceParameters parameters);   // §8.6.7 OP (strokes) / op (all else), OPM; §10.6 HT, HTO as written; saved/restored, starts off/0/default; a composite RGB backend ignores it (#116)
    void DrawGroup(in DisplayGroup group);   // §11.4/§11.6.6/§11.7.4.4 transparency group: replay group.Replay(this) into a layer (isolated/knockout/ColorSpace), composite with Opacity+BlendMode through the clip; the list skips the content itself (#114)
}

public sealed class DisplayImage                      // §8.9.5, §8.9.7: decoded once per list, one instance per image XObject
{
    public int Width { get; }  public int Height { get; }  public int Components { get; }
    public int BitsPerComponent { get; }                // logical n: raw values 0 .. 2^n - 1
    public int StorageBits { get; }  public int Stride { get; }
    public ReadOnlySpan<byte> Samples { get; }          // §8.9.3 layout (rows top first, MSB first, 16-bit big-endian)
    public ReadOnlySpan<byte> GetRow(int y);
    public PdfColorSpace ColorSpace { get; }            // resolved, before defaults; never Pattern; Indexed has 1 component
    public ImageDecodeMap DecodeMap { get; }            // §8.9.5.2; MapToIndices for Indexed
    public bool Interpolate { get; }                    // §8.9.5.3
    public DisplayImageMask? Mask { get; }              // §8.9.6.3 explicit mask, at its own size (#106)
    public DisplayImage? SoftMask { get; }              // §11.6.5.2 SMask or the JPX opacity plane (SMaskInData), own size, 1 component
    public ReadOnlySpan<double> ColorKey { get; }       // §8.9.6.4 min/max per component on raw samples; empty when none
    public ReadOnlySpan<float> Matte { get; }           // §11.6.5.2 Table 144, base-space components; zeros for SMaskInData 2
    public ReadOnlySpan<byte> ColorTable { get; }       // §8.6.6.3 Indexed table as stored; empty otherwise
}

public sealed class DisplayImageMask                  // §8.9.6.2/§8.9.6.3: 1 bit per sample, own size, interned per mask stream
{
    public int Width { get; }  public int Height { get; }  public int Stride { get; }
    public ReadOnlySpan<byte> Samples { get; }  public ReadOnlySpan<byte> GetRow(int y);
    public bool IsInverted { get; }                     // a sample 1 paints (Decode [1 0], codec polarity folded in); else 0 paints
    public bool Interpolate { get; }
}

public readonly ref struct DisplayColor               // §8.6.1: colour specification, never pre-converted
{
    public PdfColorSpace ColorSpace { get; }            // as selected (DeviceCMYK, Separation, Lab, ICCBased, ...), before defaults
    public ReadOnlySpan<float> Components { get; }      // as the operator gave them, unclipped
    public PdfDefaultColorSpaces DefaultColorSpaces { get; }   // §8.6.5.6, current at the paint
    public ColorConversion Conversion { get; }          // intent, BPC, BG, UCR from the state; Target = Rgb
}

public readonly ref struct StrokeStyle                // §8.4.3, §10.7.5: line parameters at the stroking operator, user space
{
    public double LineWidth { get; }                    // >= 0; 0 = thinnest line the device can render (one device pixel)
    public LineCap LineCap { get; }                     // Table 53
    public LineJoin LineJoin { get; }                   // Table 54
    public double MiterLimit { get; }                   // >= 1; ratio 1 / sin(phi/2), phi measured in user space
    public ReadOnlySpan<double> DashArray { get; }      // empty = solid; non-negative, not all zero
    public double DashPhase { get; }                    // >= 0 (already normalized), 0 for a solid line
    public bool StrokeAdjustment { get; }               // SA
}
```

Rules every backend follows:

- A replay starts with the identity transform: user space is the page's default user space. Mapping it to the device (scale or DPI, rotation, CropBox, UserUnit, the clip rectangle of a tile) is the backend's or its renderer's, applied under the list's transforms. Use the mapping the software rasterizer uses (#95, package `Broadside.Rendering`): `RenderOptions.GetDeviceTransform(page)` (default user space to pixels, origin top left, y down, crop box, `Rotate` plus the options' rotation, `UserUnit` times the scale) and `RenderOptions.GetPixelSize(page)` (rounded up to whole pixels), so every backend's image lines up with the rasterizer's snapshots.
- `SetTransform` comes before the paints it applies to and only when the CTM changes; `RestoreState` restores the transform, the clip (#105) and, as later tickets add them, everything else the backend keeps per state. Save/restore pairs with nothing painted between them (only transforms and clips) are dropped at build time, with what is between them.
- `PathView` is the path exactly as constructed, in user space: close open subpaths for filling, ignore a trailing single-point subpath, treat degenerate subpaths per §8.5.3.2/§8.5.3.3.1. Spans and views are valid only during the call: copy what you keep.
- Colour: convert with `list.Document.GetColorConverter(color.ColorSpace, color.Conversion with { Target = <your model> }, color.DefaultColorSpaces)`. That expands Indexed, Separation, DeviceN, applies the defaults and goes through the engine's `IColorManagement` (the colour-management extension point). Check `PdfColorConverter.PaintsNothing` (Separation `None`). Cache converters per colour space if you convert per paint; the document caches them too.
- Strokes (#99): stroke in the stroke's user space (the transform set before it) so a non-uniform CTM gives an elliptical pen; each subpath on its own, dash pattern restarted per subpath, closed subpaths joined where they close, the last and first dash of a closed subpath joined when both are on, a degenerate subpath a dot only with round caps, a lone moveto nothing, zero-length dashes painted with their caps along the path, width 0 one device pixel. The software rasterizer's `Stroker` (outline polygons, non-zero fill, round joins between the flattened pieces of a curve, at most 2^20 dashes per stroke) and `paths-strokes.pdf` are the reference; a stroke in a Pattern colour is not in the list yet.
- Clips (#105): `IntersectClip` intersects the current clip with the inside of the path (the area `FillPath` would fill with that rule) under the current transform; it arrives after the paint of its path object, and a form's bounding box arrives the same way inside the state saved around the form. `RestoreState` brings back the clip of the matching `SaveState`. The replay starts with the initial clip, the page area your renderer maps (the crop box). Anti-alias clip edges like fill edges. The software rasterizer's reference: `RasterClip` (a device rectangle for axis-aligned rectangles, the no-mask fast path, times a pooled 8-bit coverage mask for other paths), with every paint's coverage going through `ScanlineRasterizer.Paint`/`Fill` so strokes, images and shadings are clipped too. Text clips (§9.3.6, #107) arrive as an ordinary `IntersectClip` at the end of the text object: the glyph outlines placed in user space as one path, non-zero rule; nothing text-specific to implement.
- Shadings (`DrawShading`, `FillPathWithShading`, `StrokePathWithShading`, #109): `DisplayShading.Shading` is the resolved model (`PdfAxialShading`, `PdfRadialShading`, ... with geometry, Domain, Extend, Background, BBox, AntiAlias and `EvaluateFunction`); `DisplayShading.Matrix` maps its target space to default user space (the CTM at `sh`, pattern space for a pattern; independent of `SetTransform`, which still places the path). `sh` fills the whole current clip and ignores the Background; pattern paints fill the Background outside the shading's bounds (`PaintsBackground`). Convert the function's colours with `GetColorConverter(shading.Shading.InterpolationColorSpace, shading.Conversion with { Target = ... }, shading.DefaultColorSpaces)` and never interpolate after conversion (§8.7.4.4). Native gradients fit Types 2 and 3 (Extend = clamp vs. decal; radial must take the greatest s, §8.7.4.5.4). The software rasterizer's reference: `ShadingSource` (a 1024-entry table of converted colours per paint), `ShadingGeometry` (s per point) and `ShadingPainter` (a coverage sink of `ScanlineRasterizer.Paint`, so the clip applies). The list carries Types 1 and 4 to 7 too; the rasterizer skips them until #110/#111.
- Images (`DrawImage`, #102): image space maps to the unit square through `[1/Width 0 0 -1/Height 0 1]` (first row at the top), then the current transform. Map samples through `DecodeMap` (Indexed: `MapToIndices`), convert with `GetColorConverter(image.ColorSpace, conversion with { Target = ... }, defaultColorSpaces)` (the conversion's intent is already the image's Intent entry when it has one), resample as your platform does; honour `Interpolate` when enlarging. Key per-surface caches on the `DisplayImage` instance.
- Masks (#106): a mask and its image both map onto the unit square whatever their sizes, so resample each from its own grid (never decode a mask at the image's size). `Mask` (1 bit, `ImageRows.Stencil` gives 255 where it paints) and `ColorKey` (on raw samples, `ImageRows.ColorKey`) punch holes; `SoftMask` values through its own `DecodeMap` are opacities; remove `Matte` from the component values before conversion (`ImageRows.Unpremultiply`; Indexed: the table's base-space colours from `ColorTable`), then composite premultiplied. `FillImageMask` paints the colour where the stencil paints, resampled like an image. The software rasterizer folds a mask of the image's size into the converted pixels' alpha (`ImageSource`) and samples one of another size on its own grid (`MaskSource`, `ImagePainter`), every image and stencil paint going through `ScanlineRasterizer.Paint` so the clip applies. Stencil masks in a Pattern colour are not in the list yet.
- Annotations (#98): `PdfPage.CreateDisplayList(DisplayLayers, DisplayIntent, ContentOptions)` builds the content, annotation and form-field layers (`RenderOptions.Layers`, All by default); between `BeginAnnotation` and `EndAnnotation` come the appearance's paints, already placed by AA. `BeginAnnotation` saves the state as `SaveState` does. For `NoZoom`/`NoRotate` (§12.5.3, Figure 78) map default user space to the device about `Rectangle`'s upper-left corner: keep the image of that corner, drop the device transform's scale (to one pixel per unit) and/or its rotation (to upright, y flipped), until `EndAnnotation`. Composite the appearance as a group with `Opacity` (the annotation's ca) and `BlendMode`; the software rasterizer clips to the whole pixels around the rectangle and paints a translucent annotation (or one in a blend mode other than Normal) into one of its transparency-group layers, isolated and knockout as `Isolated`/`Knockout` say, composited at `EndAnnotation` (`SoftwareRasterizer.Annotations.cs`, `SoftwareRasterizer.Groups.cs`).
- Transparency groups (#114): `DrawGroup(in DisplayGroup)` hands over a group XObject (`Transparency`), the page group (`Page`, always isolated, composite onto white in its `ColorSpace`) or the implicit knockout group of a translucent fill and stroke (`FillAndStroke`). The list does not replay the content: call `group.Replay(this)` (once or more, e.g. per colour plane) between your own layer begin and end. A backend without layers may replay directly: exact for a non-isolated, non-knockout, Normal, opacity-1 group, an approximation otherwise (report a diagnostic). The software rasterizer's design (layers the size of the group's bounds with a clip origin, knockout and alpha/shape tracking through `ScanlineRasterizer.Hook`, gray/CMYK pixel models, a probe that paints a group directly when that is the same) is in `GroupLayer` and `SoftwareRasterizer.Groups.cs`.
- Text (`DrawGlyphs`, #100): each glyph maps glyph space -> user space through `run.GetGlyphTransform(i)` (program FontMatrix x [HorizontalScale 0 0 1 0 0] x TextMatrix), then the current transform. Outline backends fill `run.GetOutline(i)` non-zero with `FillColor` when `Fills`, then stroke the outline mapped to user space with `StrokeStyle`/`StrokeColor` when `Strokes`, glyph by glyph (mode 2 fills then strokes each glyph). A run with neither (mode 3, invisible) paints nothing; it is in the list for hit-testing. A native backend may draw `run.Program` glyph ids with its font engine instead, but must use the outlines when `RenderOptions.ForceOutlines` is set (golden-image comparison). The shared API for native glyphs (#123; #127, #131, #135 reuse it, add nothing parallel): `FontProgram.TryGetSfntData(out ReadOnlyMemory<byte> data, out int faceIndex)` gives the whole sfnt file of an embedded TrueType or OpenType-CFF program read without any repair (false for bare CFF, Type 1, repaired programs: draw those from outlines); glyph ids are the program's. A program the engine refuses, or a glyph whose engine outline differs from the program's, is drawn from outlines and reported once per render as the Information diagnostic `BackendNativeGlyphsUnavailable`. Golden tests compare native text under `GoldenThreshold.Text` (plus a per-backend `GoldenThresholds` row when needed, e.g. `coregraphics-text`) and forced outlines under the table threshold or `GoldenThreshold.Tight` against a reference. `HorizontalScale` is 1 except for glyphs drawn with a substitute (PDF width / substitute width). Outlines are interned per (program, glyph id) in the list: key glyph caches on the outline or the (program, glyph id) pair. Text clips (#107) come as `IntersectClip` (above).
- Tiling patterns (`FillPathWithTilingPattern`, `StrokePathWithTilingPattern`, #112): `DisplayTilingPattern.Cell` is the cell already built into a display list whose default user space is pattern space (an uncoloured pattern's colour is baked in, its transparency state starts at the defaults, §11.6.7), clipped to the BBox; `Matrix` maps pattern space to default user space (independent of `SetTransform`, which places the path); `Pattern` gives BBox, XStep, YStep (either may be negative) and TilingType. Replicate the cell at (i × XStep, j × YStep) in pattern space over the painted area, overlapping where the steps are smaller than the BBox, and composite the tiled result as one object with the paint's alpha and blend mode. Every paint with the same pattern on a page hands over the same `Cell` instance: key per-surface caches (tile bitmaps, CGPattern, picture shaders, image brushes) on it. The software rasterizer's reference: `SoftwareRasterizer.Tiling.cs` (the cell rendered once per paint through a child backend into a scratch bitmap; TilingType 1/3 round the steps to whole pixels, 2 rounds each tile's position; the BBox corner snapped to the pixel grid; tiles laid into a layer, then `TilingPainter` composites it through `ScanlineRasterizer.Paint`). Glyph runs and stencil masks in a tiling pattern are not in the list yet.
- Type 3 glyphs (#108) need nothing from a backend: the list carries each glyph's description as the ordinary calls it paints (transforms, fills, strokes, clips, image masks, nested glyph runs) under the glyph's transform, a d1 glyph already in the text's colours. The builder interprets each description once per font, code and inherited state and copies its records at every show, so a backend sees no difference between a Type 3 glyph and the same marks on the page.
- Transfer functions (#116): nothing to do. They travel in each colour's `ColorConversion.TransferFunction` (and an image's or shading's conversion) and the converter from `GetColorConverter` applies them to the device colour; keep the `TransferFunction` when you replace `Target`. Overprint and halftones arrive through `SetDeviceParameters`; a screen backend ignores them (§8.6.7: a device that does not overprint ignores the overprint parameter; §10.6.1: no halftoning on continuous-tone devices); overprint preview (#227) is the software rasterizer's `RenderOptions.OverprintPreview` (colourant planes in `SoftwareRasterizer.Overprint.cs`), a backend that wants it can follow that model.
- Not in the list yet (later Phase 3 tickets): transparency groups and soft masks.

A backend must also, as those operations arrive:

- draw clipping (path and text, intersect), decoded images with transforms and resampling, shadings 1–7, tiling patterns, glyph runs (font reference + glyph ids + positions, native glyph rendering where the platform has it with an outline fallback when `ForceOutlines` is set), and the transparency model (§11: isolated and non-isolated groups, knockout, soft masks, the 16 blend modes, constant alpha);
- honour the render options of Track 3A: scale or DPI, rotation, clip rectangle (tiled region rendering: `RenderOptions.Region`, whose `GetPixelSize`/`GetDeviceTransform`/`GetPixelRectangle` already describe the region's pixels, and `DisplayList.Replay(backend, region)` with the target's pixels mapped back to default user space and widened by whatever the backend paints beyond a shape's outline, as the rasterizer does with 2 px, #96), layer selection (annotations and forms are separate replayable lists), rendering intent, anti-aliasing, cancellation and progress (#97: `RenderOptions.CancellationToken`/`Progress`; build with `ContentOptions` carrying the token, replay through `DisplayList.Replay(backend, token, progress)` or `BeginReplay`, map build progress to 0-0.5 and drawing to 0.5-1 as the rasterizer does);
- survive a sliced replay: `DisplayList.BeginReplay` may hand the operations over across many calls, with the host presenting the surface between them, so keep the graphics state, clip and target alive between `Continue` calls and expect a partial image to be shown (offer a `BeginRender` returning a `ProgressiveRender`-like handle, like `SoftwareRasterizer`);
- keep per-surface resource caches (glyphs, images, shaders) within the deterministic memory budgets the viewer relies on;
- fall back to the software rasterizer for any group or blend it cannot express (plan, Track 3D) rather than approximate silently, and record a `Diagnostic` when it does;
- allocate nothing per operation, glyph or scanline during replay; buffers are pooled per surface (`CLAUDE.md`, "Code conventions");
- render each corpus page at `GoldenCorpus.Dpi` (72) through `GoldenCorpus.CreateRenderOptions()` so the golden-image harness (#120) can compare it with the rasterizer's golden image; any 8-bit four-channel layout works (`GoldenPixelFormat`: BGRA or RGBA, premultiplied or straight, transparent or white page).

Testing against the contract: `Broadside.TestSupport.RecordingBackend` records every call as a line (`save`, `restore`, `transform [a b c d e f]`, `fill nonzero|evenodd M x y L ... Z | Family c0 c1 ...`, `stroke width Cap Join miterLimit [dash ...] phase [adjust] M ... | Family c0 c1 ...`, `clip nonzero|evenodd M x y L ... Z`, `image WxH Family bpc N[ interpolate][ mask WxH[ inverted]][ smask WxH Family bpc N][ matte m ...][ colorkey min max ...]`, `imagemask WxH[ inverted][ interpolate] | Family c0 c1 ...`) and keeps each fill's and stroke's colour space, components, defaults and conversion (`Fills`, `Strokes`), each image paint (`Images`) and each stencil mask paint (`ImageMasks`); `Broadside.Tests.Rendering.DisplayListTests` shows the pattern. `DisplayListBenchmarks` (Build, Replay) is the replay allocation baseline.

Registration goes through the options object (`PdfOptions.Use*`, plan row 1.12) or the package's one fluent configuration call, the same shape as `Broadside.Fonts.Standard14` (ADR 0007). No static registry: two engines in one process may use different backends, and the viewer selects one per surface.

## Managed default

The software rasterizer in `src/Broadside.Rendering/` is the default and the oracle: fully managed, `System.*` only, on every platform. Since #95: `SoftwareRasterizer.Render(page[, options])` returns a pooled `Bitmap` (premultiplied BGRA8, white page), `Render(page, bitmap, options)` draws into caller memory, `Render(list, bitmap, deviceTransform)` replays a cached list without a background; `Bitmap.SavePng` writes PNG. Its private backend (`SoftwareRasterizer.Backend`) is where a new `IRenderingBackend` member gets its reference implementation; scan conversion is `ScanlineRasterizer` (exact-area cells, both fill rules, zero allocation once warm: keep it that way, `RasterizerAllocationTests` and `RasterizerBenchmarks` guard it). Its renders of every corpus page are the golden images in `tests/Golden/` (#120: `GoldenImageTests`, compared perceptually through `tests/Broadside.GoldenImages`); its older per-file snapshots (`tests/Broadside.Rendering.Tests/Snapshots/*.verified.png`) compare by decoded pixels (`PngSnapshots`), and `tests/Broadside.Rendering.AotSmoke` re-checks them under Native AOT. Native backends are exempt from the managed rule (ADR 0001) but are never the default and never a dependency of the core.

## Deliverables of a backend PR

1. Package `src/Broadside.Rendering.<Name>/` with `PublicAPI.Shipped.txt`/`Unshipped.txt`, a `Description` in the csproj, and the platform conditioning the existing backend projects use; added to `Broadside.slnx` under `/src/` (and to `Broadside.Core.slnf` only if it builds everywhere).
2. XML docs citing the clauses each operation implements (`<remarks>ISO 32000-2 §8.5.3</remarks>` for path painting, `§11.3` for compositing, `§9.3` for text state); the backend contract itself cites ADR 0006.
3. Conformance rows: the backend-affected clauses in §8, §9.3–§9.4, §10 and §11 of `docs/conformance/iso-32000-2.md` with the snapshot tests named; the rows stay `partial` until the golden-image suite passes within threshold.
4. Test project `tests/Broadside.Rendering.<Name>.Tests/` (xUnit v3, `InternalsVisibleTo` granted on its own package only by `src/Directory.Build.props`) referencing `tests/Broadside.GoldenImages`. It renders corpus pages and compares them with the rasterizer's golden images through the harness, never with its own snapshots:

   ```csharp
   [Theory]
   [MemberData(nameof(GoldenCorpus.Pages), MemberType = typeof(GoldenCorpus))]   // or GoldenCorpus.PagesOf("paths-fill-rules.pdf", ...)
   public void Page_matches_the_golden_image(string fileName, int page)
   {
       using PdfDocument document = GoldenCorpus.Open(fileName);                   // password files open with their user password
       RenderOptions options = GoldenCorpus.CreateRenderOptions();                  // 72 DPI; GetPixelSize / GetDeviceTransform
       // ... render document.Pages[page] onto a surface of options.GetPixelSize(page) ...
       GoldenCorpus.AssertMatchesReference("<name>", fileName, page,
           GoldenImage.FromPixels(pixels, width, height, rowBytes, GoldenPixelFormat.Bgra8Premultiplied));
   }
   ```

   A failure writes `tests/Golden/<file>.page<N>.<name>.received.png` and `.diff.png` (red: beyond tolerance, amber: tolerated). A page that legitimately differs more than `GoldenThreshold.Default` gets a row, with its reason, in `GoldenThresholds.Rules` (`tests/Broadside.GoldenImages/GoldenThresholds.cs`), the one reviewed table.
5. A CI leg on the backend's platform (ubuntu, windows or macos matrix entry) that builds and runs that test project.
6. Fuzz: none for a backend (it consumes a trusted display list), but any new decoder the backend introduces gets a target.
7. Benchmark `<Name>BackendBenchmarks` with `[MemoryDiagnoser]`: replay of the corpus display lists at a fixed DPI, `Allocated` at `-` (skill `adding-a-benchmark`); these feed the Track 3I regression gate alongside the rasterizer's numbers.

## Backends that only draw on a device: Android (#133)

`src/Broadside.Rendering.Android/` is `AndroidCanvasBackend` (public: `Render(page[, options])` -> `Android.Graphics.Bitmap` on white, `Render(page, Canvas, options)` on white clipped to the page's pixels, `Render(DisplayList, Canvas, in Matrix deviceTransform)` without a background; the canvas is always left as found). Its private `Backend` maps fill and clip paths to device space in managed code (doubles, clamped to ±2^30) and hands the canvas device coordinates; strokes are built in user space and drawn under `canvas.concat` of the CTM (set through `setSinCos`/`preScale`/`preSkew`/`postTranslate`, because `Matrix.setValues(float[])` makes a Java array per call), except the thinnest line (width 0, or SA under half a pixel), which is a device-space pen of `MathF.BitIncrement(1f)` (at exactly one pixel Skia draws a hairline, whose coverage differs from the rasterizer's). It copies the rasterizer's degenerate-subpath dots, SA width rounding and vertex snapping. Skia quirks it works around: odd dash arrays are doubled; zero-length dashes get 1/256 px (else square caps stay upright); open dashed subpaths are extended 1/256 px (else a dash starting exactly at the end is dropped). Android enum constants (`Paint.Cap.Round`, ...) are read once into static fields; dash effects are cached per pattern (32 entries).

Tests: the Canvas only exists on a device, so `tests/Broadside.Rendering.Android.Device` (an Android app; same platform gate) has an `Instrumentation` that renders the corpus files the host names (all of `tests/Corpus/*.pdf` are assets), writes raw BGRA to its external files dir and measures warm replays with `Allocations.Measure` (plus a probe proving the runtime counts allocations); `tests/Broadside.Rendering.Android.Tests` (host, net10.0, not in `Broadside.Core.slnf`) installs the APK over adb, runs the instrumentation once, pulls the pixels and calls `GoldenCorpus.AssertMatchesReference("android", ...)`; it skips without adb, a device or the APK unless `BROADSIDE_ANDROID_REQUIRED=1`. The two share `DeviceProtocol.cs`. Locally: build the app (`dotnet build tests/Broadside.Rendering.Android.Device -c Release -p:RuntimeIdentifier=android-arm64`, add `-p:JavaSdkDirectory=...` if the Java SDK is not found), start an emulator, `dotnet test tests/Broadside.Rendering.Android.Tests`. CI: `.github/workflows/android.yml` (weekly and on Android PRs). The device-side replay measurement replaces the `<Name>BackendBenchmarks` class: BenchmarkDotNet does not run on Android. For #134/#136: add the corpus files to `AndroidBackendTests.Files` and implement the skipped `IRenderingBackend` members.

Text (#135, `AndroidCanvasBackend.Text.cs`): glyphs of programs whose `FontProgram.TryGetSfntData` returns the sfnt bytes are drawn by `Canvas.drawGlyphs` (API 31+) with an `android.graphics.fonts.Font` built once per program per backend from a direct `ByteBuffer` (`ConditionalWeakTable` keyed on the program, 64 kept); each glyph is checked once (`Font.getGlyphBounds` at 64 px against the outline's control box, 2.5 px) and drawn from its outline when it disagrees. The fill paint carries `SubpixelText | LinearText`, hinting off, text size 16; the canvas matrix is `Scale(1/16, -1/16) x FontMatrix^-1 x glyphToDevice`, and consecutive filled glyphs whose matrices differ only in translation go in one call. `drawGlyphs` is called through Java.Interop (`JniEnvironment.InstanceMethods.CallVoidMethod`) with Java arrays the backend keeps, because the binding creates two Java arrays per call. Everything else (other formats, `ForceOutlines`, font matrices that skew or rotate, API < 31, a program Android cannot load, a glyph that disagrees) fills the outline mapped to the device (non-zero, no degenerate dots) and strokes it in user space through `StrokePath`; the last three report `BackendNativeGlyphsUnavailable` (Information). Device tests render each page three ways (native, forced outlines, and `AndroidPathReference`, an independent `IRenderingBackend` in the device app that fills outlines as plain Android paths) and report `native-glyphs:`/`fonts:` counters (the device app has `InternalsVisibleTo`). `RenderOptions.With*` mutate the instance: build a separate options object for forced outlines.

Images, shadings, patterns (#134, `AndroidCanvasBackend.Images/.Shadings/.Patterns.cs`): CoreGraphics' managed `ImageConverter`/`ImageReducer`/`ImageCache`/`MeshRasterizer`/`MeshTriangles` copied with the namespace changed; `PixelImage` keeps the managed BGRA/alpha pixels plus an ARGB_8888/ALPHA_8 `Bitmap` filled once through a direct `ByteBuffer` over pinned memory (B and R swapped: Android stores RGBA). Pixel space = canvas coordinates when the canvas matrix (read at `Begin` via the deprecated `Canvas.getMatrix(Matrix)` and three `MapRect` point images, no Java array) is a whole-pixel translation, else that matrix. Axial = `LinearGradient`, radial = two-point conical `RadialGradient` with `long` colours (API 31+; it refuses an end radius of 0, use a millionth of the start radius; before 31 only growing concentric circles, else `BackendShadingUnsupported`). **The canvas draws an ALPHA_8 bitmap as coverage of the paint's colour**, so a `DstIn` paint on the bitmap does nothing: masks of another size go into their own layer (`saveLayer` with a `DstIn` paint) drawn plainly. Strokes with shading/pattern: outer layer (stroke alpha/blend) holding the stroke drawn black, inner `SrcIn` layer. Tiling: nested `Backend` sharing the caches renders the cell into a bitmap tile on the rasterizer lattice; whole-pixel tiles repeat through a `BitmapShader` (REPEAT, local matrix = the tile's corner), sub-pixel or rotated lattices draw each tile. Device app links the synthetic samples (`DeviceProtocol.Samples`, names `sample-*.pdf`) and reports `images-N:`/`cells-N:`/`cached-bytes:` counters from held display lists (a new list has new images, so counts double otherwise) and an `uncached` variant (zero image budget).

Transparency (#136, `AndroidCanvasBackend.Groups.cs`): CoreGraphics' `GroupInspector` decision on the canvas. Isolated and non-blending groups: `Canvas.saveLayer(bounds, paint)` with the group's alpha and blend mode; a group or state soft mask is an ALPHA_8 bitmap of the rasterizer's mask values drawn plainly into a nested `saveLayer(null, DstIn)` (a DstIn paint on an A8 bitmap does nothing: it draws as coverage). Masked paints draw in Normal into a layer composited with their blend mode (`BeginMasked`/`EndMaskedPaint`; paint members are `XCore`). The fill and stroke's knockout group: a layer whose paints draw with `BlendMode.Src` (the `Replace` sentinel in `SetBlendMode`, API 29+; below that rasterized). No layer starts from the backdrop, so knockout, gray/CMYK-blending and non-isolated blending groups go through `SoftwareRasterizer.Render(in DisplayGroup, ...)` as an ARGB bitmap, with CoreGraphics' diagnostics. Device tests: `AndroidTransparencyTests` (corpus transparency pages at the default threshold, no `GoldenThresholds` row; group-grid 40 000 px as CoreGraphics).

## Worked example: the Skia backend

Since #121, `src/Broadside.Rendering.Skia/` holds `SkiaBackend` (public, sealed, `IDisposable`, mirroring `SoftwareRasterizer`): `Render(page[, options])` -> `SKBitmap` (BGRA premultiplied, white page), `Render(page, SKCanvas, options)` (white page area at the canvas origin, clipped to it, under the canvas's own matrix and clip), `Render(DisplayList, SKCanvas, in Matrix deviceTransform)` (no background), and `Diagnostics` (the last render's skipped kinds). Its private `Replayer` (`SkiaBackend.Replayer.cs` state, fills, clips; `.Strokes.cs`; `.Unsupported.cs`) is the `IRenderingBackend`. How it maps the contract:

- **State:** `SaveState`/`RestoreState` are `SKCanvas.Save`/`Restore` plus a CTM stack; the canvas matrix captured at the start of a replay (`_base`) is set before every paint, so a caller's canvas transform (DPI, scrolling) composes under the list's.
- **Fills and clips** are built in device coordinates in double precision (CTM x device transform applied in managed code, clamped to ±2^30) and drawn with `_base`; a degenerate subpath adds the device pixel under its point (§8.5.3.3.1) as the rasterizer's `AddPixel` does. `IntersectClip` is `ClipPath(..., Intersect, antialias: true)`.
- **Strokes** stay in user space and are drawn under `_base` concatenated with the CTM, so Skia's stroker gives the elliptical pen. Before Skia sees them the backend applies the rasterizer's rules itself: lone movetos dropped, degenerate subpaths kept only with round caps (as a zero-length segment), and, when the stroke is dashed or adjusted, the subpath flattened exactly as `Stroker` flattens it (0.1 px, points inside curves marked smooth) so that stroke adjustment (width rounded, the vertices of axis-aligned device segments not inside curves snapped, including a closed subpath's zero-length closing segment) and dashes (cut in user space, restart per subpath, zero-length dashes as a 1e-3 segment along the path so the cap turns, the held-back head dash of a closed subpath appended after the tail so they join, 2^20 dash budget) move and cut the same points. The thinnest line (width 0, or SA under half a pixel) is mapped to device space and stroked 1 px wide. Widths of exactly one device pixel are drawn 1/1024 px wider: Skia draws strokes up to one device pixel wide as hairlines, whose coverage differs. Never `SKPathEffect.CreateDash` or `SKPathMeasure.GetSegment`: both allocate, and the dash effect's closed-path and zero-length semantics differ.
- **Allocation:** in SkiaSharp 4 every path handed to the canvas is a new managed `SKPath` (`SKPathBuilder.Snapshot`/`Detach` allocate one; `SKPath`'s obsolete in-place methods allocate a builder per rebuild, and `Rewind` too). So the replayer records each operation's geometry (with its fill type) in a kept managed `PathRecorder` and gets the `SKPath` from `PathCache`, keyed by a hash of the geometry and checked for equality, built once per distinct geometry and kept up to 2^21 coordinates and 2^16 paths (then emptied). Fills and clips are recorded in device coordinates, so a different device transform misses the cache; strokes in user space (except the thinnest). Diagnostics are static immutable instances added once per kind, so a warm replay allocates 0 B (`SkiaAllocationTests`, `SkiaBackendBenchmarks`). Measure any new SkiaSharp call with `GC.GetAllocatedBytesForCurrentThread` before using it on the replay path.
- **Glyphs (#123, `SkiaBackend.Text.cs`, `.Typefaces.cs`):** outline fills are recorded in glyph space and drawn under the canvas matrix, so the path cache hits once per glyph; strokes use `StrokePath` on the outline mapped to user space. Native glyphs: one `SKTypeface` per program per backend from `TryGetSfntData` (a weak `ConditionalWeakTable<FontProgram, Face>`, at most 256 faces and 2^16 glyphs), an `SKFont` at size unitsPerEm, no hinting, subpixel, no baseline snap, no embedded bitmaps; each glyph is one `SKTextBlob` after Skia's glyph path bounds are checked against the outline (within 0.5 + upem/1000 units), else its outline. `Render(DisplayList, SKCanvas, in Matrix, bool forceOutlines)` and the page overloads' `RenderOptions.ForceOutlines` select outlines. Measured on macOS (CoreText under Skia): native small text is lighter (ink 0.78-0.87) and up to ~0.75 px taller, and a CFF glyph with opposite-winding overlapping contours is filled where non-zero leaves a hole: hence `GoldenThreshold.Text` = (0.8, 0.05, 8). Each kind's diagnostic has its own bit in the replayer's once-per-render mask (`Report(bit, ...)`): give a new kind a free bit.
- **Images and masks (#122, `SkiaBackend.Images.cs`, `ImageConverter`, `ImageReducer`, `ImageCache`):** each interned `DisplayImage`/`DisplayImageMask` converts once per backend to an `SKImage` (premultiplied BGRA as the rasterizer's `ImageSource`; masks Alpha8, painted in the paint colour), kept in an LRU within the document's `ImageCacheBudget` (read from `CacheStatistics.Images.Budget` once per document; 0 = convert per paint, same pixels). Skia's own sampling does not match the rasterizer's (mipmaps blur reductions; its float nearest picks the other sample where a pixel centre lies on a sample boundary), so `ImageReducer` resamples to the device pixels with the rasterizer's `ImagePainter` rules and arithmetic (box/Points/tent/nearest per axis, the inverse transform stepped along the spans its scan converter emits) for the first four transforms per image (`ImageCache.Entry.Admit`; later ones go to Skia so a Type 3 mask at 2,000 positions allocates nothing warm), clipped to the outline with AA. Masks of another size are drawn `DstIn` in a layer.
- **Shadings (#122, `SkiaBackend.Shadings.cs`, `ShadingBuilder`, `ShadingCache`):** built once per `PdfShading` + conversion in shading space: axial/radial = `SKShader` linear/two-point-conical gradients, 256 stops sampled from the function, hard transparent stops for ends not extended; Type 1 = a 256x256 texture of the function over its domain; Types 4-7 = `SKVertices` (patches cut 16x16 per patch, v then u order; non-RGB/gray spaces split triangles 4x4; a function's t is a texture coordinate into a 1024-entry colour table shader, so t is interpolated). Paint: fills clip to the device path then `DrawPaint`/`DrawVertices`/`DrawImage` under the shading matrix, BBox clipped, Background first (in a layer when translucent); strokes use two layers (outer = stroke coverage with alpha/blend, inner `SrcIn` = the paint) because Skia blend modes only touch drawn pixels. The AntiAlias hint (the rasterizer supersamples 2x2) is not honoured.
- **Tiling patterns (#122, `SkiaBackend.Tiling.cs`):** the cell list is recorded into an `SKPicture` by a nested `Replayer` (one per depth, max 8; caches and diagnostics shared with the root) and repeated by `SKPicture.ToShader(Repeat, Repeat, Linear, tile)`; the lattice is laid out like `TilingLayout` (types 1/3 and tiny steps rounded to whole pixels, BBox corner on the grid), upright lattices recorded under their own scale so tiles are whole-pixel translations; overlapping cells are recorded as extra copies in the tile (max 256). Cached per cell `DisplayList` and recording scale (`CellsRecorded` counter). Type 2 lattices keep exact sub-pixel offsets (the rasterizer rounds each tile).
- **Transparency (#124, `SkiaBackend.Transparency.cs`):** a no-paint `GroupInspector` replay decides per group: plain content replays directly; isolated (or non-blending) groups are `SaveLayer`s with opacity/BM, the group's soft mask applied by `DstIn` before the restore; non-isolated blending content at opacity < 1 is an `InitializeWithPrevious` layer restored with `SKBlender.CreateArithmetic(0, a, 1 - a, 0)`; the fill-and-stroke knockout group is a layer whose paints draw with `Src` (`PaintBlend`). Everything else (explicit knockout, gray/CMYK blending, non-isolated blending content with a BM or mask) goes through the public fallback seam `SoftwareRasterizer.Render(in DisplayGroup, PdfDocument, Bitmap, deviceTransform, transform, strokeAlpha, fillAlpha, blendMode)` (the content starts with the state the backend held: pass the CTM and compositing) and is drawn as an image. Soft-mask values come from the rasterizer (`Render(mask.Content, ...)`, luminosity/TR per pixel) as an Alpha8 image cached per (Content, placement, clip), and every paint method is wrapped (`XCore` + `BeginMasked`/`EndMasked`): paint into a layer with SrcOver, `DstIn` the values, restore with the paint's BM. The other platform backends can reuse the same seam for their fallbacks.
- **Still reported:** `BackendImageTooLarge`, `BackendShadingUnsupported` (unknown type), `BackendTilingPatternApproximated`, and the transparency fallbacks above (`BackendKnockoutGroupRasterized`, `BackendGroupColorSpaceRasterized`, `BackendSoftMaskRasterized`, Information; `BackendNonIsolatedGroupApproximated`, Warning).
- **Tests:** `PaintGoldenImageTests` (#122: every image, mask, shading and pattern corpus page under the table threshold, plus five synthetic pages against the rasterizer under thresholds stated in the test), `SkiaImageCacheTests`, `TextGoldenImageTests` (every text page: native under `GoldenThreshold.Text`, forced outlines under the table threshold and under `GoldenThreshold.Tight` against the test-side `SkiaPathReference`), `NativeGlyphTests`, `PathGoldenImageTests` (the three path files through `GoldenCorpus.AssertMatchesReference("skia", ...)`; default threshold except one reviewed `GoldenThresholds` row allowing the two inner-corner pixels of paths-strokes band B that Skia's analytic AA leaves at 92 %), `UnsupportedOperationTests`, `SkiaAllocationTests` (Heavy). Linux needs `SkiaSharp.NativeAssets.Linux.NoDependencies` (test and bench projects only; SkiaSharp itself ships the Windows and Apple natives); the existing `build-test` matrix runs the project on all three operating systems.

#124 maps groups and soft masks to `SKCanvas.SaveLayer` and falls back to the rasterizer per group as above; a GPU canvas (`SKSurface.Create(GRContext, ...)`) needs nothing else (`TransparencyTests` creates a Metal context through `MTLCreateSystemDefaultDevice` and skips without one).

## Landed: the CoreGraphics backend (#125)

`src/Broadside.Rendering.CoreGraphics/` (net10.0-macos, -ios, -maccatalyst; depends on `Broadside.Rendering` and the Apple bindings only). Public: `CoreGraphicsRenderer` (IDisposable, reusable, one render at a time): `Render(PdfPage, CGBitmapContext, RenderOptions)` (top-left page area of a bitmap context in its default y-up space, on white, clipped to the page; flips internally) and `Render(DisplayList, CGContext, in Matrix deviceTransform)` (the transform maps default user space to the context's current user space, so a flipped view's context takes `RenderOptions.GetDeviceTransform` as is). Internals to extend for #126-#128:

- `CoreGraphicsBackend` keeps the CTM itself (CoreGraphics can only concatenate): fills and clips are built from points it maps to the context's space; strokes concatenate the CTM inside a saved state. `SaveState`/`RestoreState` pair with `CGContext.SaveState`/`RestoreState`, so anything set on the context (clips, later blend modes, alpha) restores with them. Colours are converted to RGB through the document, quantized to 8 bits, and set as sRGB components (`SetFillColorSpace(sRGB)` once per replay) through a kept `nfloat[]`, so nothing allocates per paint.
- `CoreGraphicsStroker` flattens strokes, cuts dashes and applies stroke adjustment exactly as the rasterizer's `Stroker` does, then hands CoreGraphics plain polylines to outline (caps, joins, miter limit are CoreGraphics'). Do not hand dashed paths to `CGContext.SetLineDash`: CoreGraphics caps the last dash of a closed subpath instead of joining it to the first and drops a zero-length dash at the end of an open subpath, both visible against the golden images.
- Images, shadings and stencil masks are empty members today (#126).
- Glyph runs (#127, `CoreGraphicsBackend.Text.cs`): programs whose `FontProgram.TryGetSfntData` returns face 0 of the sfnt bytes are filled through a `CGFont` (one per program per renderer, in a `ConditionalWeakTable`; refused, and reported once per render as BackendNativeGlyphsUnavailable, when CoreGraphics cannot load it, its glyph count differs or the bytes are another face of a collection; drawn from outlines without a report when the run's font matrix is not 1/unitsPerEm), one `ShowGlyphsAtPositions` per glyph with the text matrix [upem 0 0 upem 0 0] x glyphToUser x toDevice at font size 1 (`CGContextSetFontSize` and `CGContextSetShouldSubpixelQuantizeFonts` P/Invoked: no binding); font smoothing off, subpixel positioning on, both graphics state. Everything else, and every glyph under `ForceOutlines` (the page overloads' `RenderOptions.ForceOutlines`, and `Render(DisplayList, CGContext, in Matrix, bool forceOutlines)` as Skia and Android have it), fills the outline mapped to the context (no degenerate-subpath dots); strokes always use the outline in user space through `CoreGraphicsStroker`. Glyph I of text-opentype-cff-embedded has overlapping contours of opposite direction: non-zero correctly leaves the overlap empty, CoreGraphics' CFF scaler fills it (a reviewed `coregraphics-text` row in `GoldenThresholds`). Warm replay of 2,000 glyphs allocates 0 B natively and from outlines.
- Images, shadings and patterns (#126): `ImageConverter`/`ImageReducer`/`ImageCache` are Skia's (#122) with `PixelImage` (managed pixels + `CGImage`; masks are 8-bit DeviceGray images used through `ClipToMask`) in place of `SKImage`. Resampling, mesh rasterization and the tiling lattice run in the rasterizer's own device space when the context's CTM is the device up to a flip and a whole-pixel offset (else in device pixels via the CTM): pixel-centre ties then fall as the rasterizer's do. Axial/radial are `CGShading` over a `CGFunction` table (Extend native); meshes are rasterized by `MeshRasterizer` (no native Gouraud; reported as Information `BackendMeshShadingRasterized`), 4 device rasters per shading, then one shading-space texture. Tiling cells render once per scale into a bitmap tile drawn per lattice cell, not through `CGPattern` (its matrix is relative to the context's default user space, which CoreGraphics does not expose). Strokes with a shading or pattern clip to `CoreGraphicsStroker.Outline` (`ReplacePathWithStrokedPath`). Pattern cells replay through a nested `CoreGraphicsBackend` sharing the caches.
- Transparency (#128, `CoreGraphicsBackend.Groups.cs`): Skia's `GroupInspector` decision, on CoreGraphics. Isolated and non-blending groups: `SaveState`, `ClipToMask` (group soft mask), `SetAlpha`/`SetBlendMode`, `BeginTransparencyLayer` (CoreGraphics applies a mask clipped before the layer once, at the composite); fill-and-stroke knockout: a layer whose paints draw with `CGBlendMode.Copy` (lerps by coverage). No layer starts from the backdrop, so a non-isolated group of blending content is rasterized (`BackendNonIsolatedGroupRasterized` Information when its paints share one mode, else `BackendNonIsolatedGroupApproximated`); knockout and gray/CMYK-blending groups too, through `SoftwareRasterizer.Render(in DisplayGroup, ...)` with `_device * _pixels`. Soft masks: values from the rasterizer as 8-bit DeviceGray `PixelImage`s (LRU of 8 on the root backend), each masked paint is `XCore` wrapped in `SaveState` + `ClipToMask` + `RestoreState`.
- Tests: `tests/Broadside.Rendering.CoreGraphics.Tests` is a `net10.0-macos` app (platform gate like the package; in `Broadside.slnx`, not `Broadside.Core.slnf`; run by an extra macOS step in `ci.yml`/`release.yml`). It replaces xUnit's app-host check and its generated entry point (`Program.cs` pumps the main run loop, else the run never ends). Benchmarks: `bench/Broadside.Rendering.CoreGraphics.Benchmarks` (`CoreGraphicsBackendBenchmarks`), in process; long operations show a few bytes of BenchmarkDotNet host noise in `Allocated`, so the build-breaking proof is `ReplayAllocationTests` (Heavy).
- Locally, build and test it with the SDK that has the `macos` workload; a deprecated `~/Library/Preferences/{Xamarin,maui}/Settings.plist` makes the app projects warn, which `-warnaserror` turns into errors (not in CI).

## Landed: Direct2D glyphs (#131)

`Direct2DBackend.Text.cs` draws filled glyphs of intact sfnt programs with `ID2D1DeviceContext::DrawGlyphRun`, one glyph per call, from a DirectWrite face (`DirectWriteFonts`: isolated `IDWriteFactory5`, an in-memory font file loader that copies each file, faces per program in a `ConditionalWeakTable`, at most 256 then everything including the loader released; faces created once per program per renderer, `Direct2DRenderer.FontFacesCreated` internal for tests). ## Landed: Direct2D images, shadings and patterns (#130)

`ImageConverter`/`ImageReducer`/`ImageCache`/`MeshRasterizer`/`ShadingBuilder` are CoreGraphics' (#126) with `PixelImage` = managed pixels + an `ID2D1Bitmap1` made on first use. Masks clip as the opacity brush of a layer (`Direct2DSurface.MaskBrush`, left untouched until the layer pops); fills, strokes and `sh` paint through `_paint` (solid, gradient or `Direct2DSurface.BitmapBrush`) whose transform is set per draw from `_paintToDevice`. Axial and nested radial shadings are gradient brushes (Extend = clips; a focal radial brush draws nested circles exactly); cone radials and meshes are rasterized per device pixel (Information diagnostics). Tiling cells draw on `Direct2DSurface.CellContext(depth)` (a second context of the same device, so bitmaps are shared) into a tile bitmap, repeated by a WRAP bitmap brush or, for fractional upright steps, drawn tile by tile at rounded positions. The renderer releases every cache on dispose and on device loss (`ReleaseDeviceResources`). The clip stack tracks device bounds (`ClipBounds`) for `sh` and tile lattices.
