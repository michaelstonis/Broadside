# v1.0.0-rc.1 gate checklist

Every exit gate of issue [#276](https://github.com/michaelstonis/Broadside/issues/276) must be green on one release-candidate commit before `v1.0.0-rc.1` is tagged. The viewer packages are part of 1.0, so every gate covers them where it applies. For each gate, the table names the workflow and job in [`.github/workflows/`](../../.github/workflows/README.md) that proves it, and how it runs:

- **PR into main**: runs on the `spec/33-broadside-v1` → `main` (or `release/*` → `main`) pull request. `ci.yml` runs in full on a pull request into `main` or from a `release/*` branch; the other workflows marked so run because that pull request changes the paths they watch (`src/**` and the rest).
- **Manual**: needs a `workflow_dispatch` run ("Run workflow", or `gh workflow run <file> --ref <branch>`) on the candidate's commit.

The **Run** column is filled with the link to the green run on the candidate's commit.

## Not a workflow

- The release notes (`CHANGELOG.md` section `1.0.0-rc.1` and the [summary](v1.0.0-rc.1-notes.md)) link the [known limitations](../known-limitations.md), the [diagnostic-code catalog](https://michaelstonis.github.io/Broadside/articles/diagnostics/) and the [API review](../api-review-v1.md).
- The [general-availability criteria](ga-criteria.md) are signed off by the owner on #276.
- `./check-api-freeze.sh` proves the freeze locally (it renames a shipped method, builds, and expects RS0017 and RS0016); no workflow runs it.
