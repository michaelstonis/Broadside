# Standard 14 font glyphs ship in a separate package

The core package carries only the metrics (AFM data) of the Standard 14 fonts, which text extraction and layout need and which are small. The glyph data (Liberation fonts under SIL OFL for Helvetica, Times and Courier; Foxit Symbol and Dingbats under BSD) ships in a separate package wired in by one fluent configuration call. Without that package, or a configured font resolver, rendering a non-embedded Standard 14 font falls back to the operating system's fonts and records a diagnostic when none match. The split keeps the core lightweight for consumers who only parse, extract or sign and never render text, at the cost of one extra package reference and configuration line for consumers who render in environments without system fonts.

## Addendum (2026-10): predefined CMap metadata in the core

The same split applies to the predefined CMaps of Table 116 and the CID-to-Unicode tables: their mappings (about 1.3 MB) ship in `Broadside.Fonts.Cmaps`, as the spec's implementation decisions say. The core keeps one small table of metadata per Table 116 name, generated from the same pinned Adobe `cmap-resources` files: the name, the character collection (Registry, Ordering, Supplement), the writing mode, the codespace ranges and the `usecmap` parent; never a code-to-CID or CID-to-Unicode mapping. Without the package that metadata is what keeps a document correct where it can be: shown strings split into codes of the right lengths (so widths, word spacing and every later glyph stay aligned), vertical writing is detected, the CIDFont's collection is checked against the CMap's (`CidSystemInfoMismatch`), and the UCS2 table a font would need is named in `CMapUnavailable` and `TextUcs2CmapMissing` (Information) so the consumer knows which package to add. Without it, a missing predefined CMap could only be read as Identity-H, which splits every multi-byte encoding wrongly and misplaces every glyph after the first single-byte code. The cost is about 7 KB of generated source and the Adobe BSD-3-Clause notice in the core's third-party notices; the package remains the only source of mappings.
