# Document signatures go through one signer interface that signs a digest

ADR 0001 requires an extension point with a managed default for each component a consumer may substitute; signing is one, because a signing key often cannot leave a hardware security module, a smart card or a remote signing service (spec open decision 10). The contract is `IPdfSigner` (namespace `Broadside.Signatures`): the signer's certificate, the rest of its chain to embed, and `SignDigest(digest, digestAlgorithm)` returning the raw signature value, with `SignDigestAsync` (defaulting to the synchronous call) for signers that wait on a device or the network; `PdfDocument.Sign` calls the first and `PdfDocument.SignAsync` the second. The core keeps everything else: it places the signature dictionary, writes the incremental update with the reserved `Contents`, hashes the byte ranges in windows through its digest facade (managed SHA-3 where the platform lacks it, issue #192), builds the CMS signed attributes, asks the signer to sign the digest of their DER encoding (RFC 5652 §5.4), and encodes the detached CMS `SignedData` itself with the BCL's `System.Formats.Asn1`. The signer never sees the document, so the same contract serves a local key, a PKCS #11 token and a cloud service, and every signer gets the same byte ranges, attributes and encoding. The managed default, `PdfCertificateSigner`, signs with the private key of an `X509Certificate2` through the platform's cryptography (RSA PKCS #1 v1.5 for issue #193; ECDSA and RSA-PSS follow with PAdES, issue #194, as new key types the encoder recognizes from the certificate, not as new members). A signer that only returns a complete CMS object is not supported: it would have to see the byte range digest and would bypass the attributes PAdES needs.

## Considered Options

- `SignedCms.ComputeSignature` from the platform PKCS package: rejected for producing the signature because it hashes the content itself from one in-memory array (a whole file for a byte range signature), cannot sign through an asynchronous or out-of-process key without a fake `RSA` subclass, and cannot compute SHA-3 digests on macOS. It stays the independent verifier in the tests.
- A signer that receives the byte range digest and returns the whole CMS object: rejected as the primary contract (see above); a consumer that needs it can still post-process, and a later ADR may add it if a service requires it.
