# Rendering goes through a display list

Interpreting a page produces a display list: a compact, device-independent sequence of fully resolved drawing operations (glyph runs with resolved font programs, decoded images, resolved color). Backends consume display lists; none of them receive content-stream operators directly. This costs one intermediate representation and one pass. It buys tile and multi-zoom caching, parallel backend replay, text hit-testing for viewers, and the ability for GPU backends to batch and to cache resources across frames, all of which an immediate-mode design cannot offer and which a viewer needs. Immediate rendering is a trivial special case (build, replay once, discard). Because the display list sits on the hottest path, it is a struct-based operation buffer with interned resources, not a tree of objects.
